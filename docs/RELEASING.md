# Выпуски и обновления

[← Сборка](../DEVELOPMENT.md)

## Что получает пользователь

Каждый опубликованный выпуск содержит четыре файла:

- `FluxReader-<версия>-release.apk` — установочный APK;
- `FluxReader-<версия>-release.apk.sha256` — его контрольная сумма;
- `FluxReader-<версия>-clean.zip` — исходники этой версии;
- `FluxReader-<версия>-clean.zip.sha256` — контрольная сумма исходников.

Тег `v<версия>` указывает на соответствующий commit. Alpha-выпуски отмечаются как prerelease, даже если это самый новый доступный APK. Для них нельзя полагаться на GitHub `/releases/latest`; в витрине используются прямые ссылки на актуальный тег.

В приложении: «Настройки → О программе → Обновления → Включая тестовые alpha-релизы». Проверка версий, загрузка APK и открытие установщика работают отдельно от офлайн-чтения. Установка требует подтверждения Android.

## Подготовка и публикация

1. Обновите `VERSION.txt`, версию Gradle и `build-info.json`, проверьте их согласованность.
2. Подготовьте описание в `docs/releases/alpha<N>.md` (для alpha) или `docs/releases/<версия>.md`.
3. Запустите `scripts/build-release.command`. Проверьте интерфейс и сертификат APK.
4. Обновите ссылки README и актуальную галерею, сохраните изменения в Git и отправьте commit в GitHub.
5. Запустите `scripts/publish-github-release.command --publish` из чистого рабочего дерева.

Скрипт не запускается автоматически. Он упаковывает исходники, создаёт draft, загружает четыре файла, сверяет имена, размеры и SHA-256 через GitHub API и только затем публикует выпуск. Уже существующий выпуск не перезаписывается. При ошибке проверки draft остаётся доступным для диагностики.

## Совместимость обновлений

`applicationId` — `io.fluxreader.app`; `versionCode` должен возрастать. Новый APK должен иметь тот же сертификат, что установленный. Текущие alpha APK подписаны исходным локальным Android debug-keystore для совместимости со старыми установками. Другая машина создаёт другой debug-keystore: его нельзя подменять при публикации.

SHA-256 текущего сертификата: `8cfb92b70fc3054b403993486438ae9a214ed749362e42ac3933c07be2f89ace`. Закрытый ключ, пароли и токены в Git не входят. Смена сертификата требует отдельного плана миграции.

## История

Теги и опубликованные GitHub Releases сохраняют предыдущие версии. Старые дубли архивов и галерей удалены из текущей ветки; их можно посмотреть в истории Git. В `docs/releases/` остаются короткие заметки последних выпусков.
